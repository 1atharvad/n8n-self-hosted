Topology is determined entirely by the `CONTABO_WORKER_IP` GitHub repository variable — **no code changes needed** to switch modes.

## Topology table

| `CONTABO_WORKER_IP` | Topology                 | Compose file                                            |
| ------------------- | ------------------------ | ------------------------------------------------------- |
| empty / unset       | Single server            | `docker/docker-compose.prod.yml`                        |
| `"1.2.3.4"`         | Multi-server (1 worker)  | `prod-main.yml` on main + `prod-worker.yml` on that IP  |
| `"1.2.3.4,5.6.7.8"` | Multi-server (2 workers) | `prod-main.yml` on main + `prod-worker.yml` on both IPs |

## What runs where

### Single server

Everything runs on one machine:
- n8n (UI + execution), n8n-worker
- fastapi (media-api)
- postgres, redis, minio, loki
- nginx, docs, admin-api, frontend, worker-monitor, promtail

### Multi-server — main server

Runs: `n8n`, `worker-monitor`, `redis`, `postgres`, `nginx`, `minio`, `admin-api`, `frontend`, `docs`, `loki`, `promtail`

The main server holds all state. The n8n web UI is on the main server.

### Multi-server — worker servers

Runs: `n8n-worker`, `worker-monitor`, `fastapi` (media-api), `promtail`

Workers handle media processing and n8n job execution. They connect to Redis on the main server for the job queue, and push logs to Loki on the main server.

## Switching from single to multi-server

1. Provision the new worker server(s) with `npm run ansible:setup:multi` locally (or the `setup-multi` custom pipeline if you use Bitbucket Pipelines).
2. Set `CONTABO_WORKER_IP` in **GitHub → Repository settings → Secrets and variables → Actions** to the worker IP(s), comma-separated.
3. Push to `main` — the next pipeline run will deploy using the multi-server topology automatically.

## Adding a worker

1. Provision the server with `setup.yml`.
2. Append the new IP to `CONTABO_WORKER_IP` (comma-separated).
3. Push — the pipeline generates a dynamic worker inventory and deploys to all IPs.

The dynamic worker inventory is generated by `sh_files/gen_workers_inventory.sh` and is not committed to git.

## Inventory files

| File                                          | Used for                               |
| --------------------------------------------- | -------------------------------------- |
| `ansible/inventory/single.yml`                | Single-server deployments              |
| `ansible/inventory/multi/main.yml`            | Multi-server: main node                |
| `ansible/inventory/multi/workers_dynamic.yml` | Multi-server: workers (auto-generated) |
